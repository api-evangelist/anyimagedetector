# AnyImageDetector

A single-purpose AI-image-detection service. The AI Image Detector API exposes a single REST endpoint that reports whether an image is AI-generated, returning a verdict, a probability score, a confidence level, and an optional per-generator breakdown.

- **Provider:** https://imagedetector.online
- **Documentation:** https://imagedetector.online/docs
- **Base URL:** https://imagedetector.online/v1
- **Tags:** AI image detection, image analysis, computer vision, content moderation, trust & safety, fact-checking, media verification, developer tools
- **Public API:** yes
- **Agent-native (MCP / llms.txt / skills):** partial — the provider serves `/llms.txt` and `/llms-full.txt` (HTTP 200, `text/plain`); no MCP server, no agent card, no published skills
- **Confidence:** 85/100

## APIs

- **AI Image Detector API** — REST API with a single endpoint (POST /v1/image/detect) that detects whether an image is AI-generated. Accepts a multipart file upload or a JSON body with a public image URL, and returns verdict, ai_score, confidence, and source_breakdown. Requires a paid account and Bearer/x-api-key authentication. (`https://imagedetector.online/v1`)

## Enrichment pass — 2026-08-11

Corrections and findings from the API Evangelist enrichment pipeline. Every claim below was probed live.

- **The provider DOES publish an `llms.txt`.** `https://imagedetector.online/llms.txt` returns 200 `text/plain`, as does `/llms-full.txt`. The original submission note said otherwise; it is saved verbatim to `llms/`. Note that it describes marketing pages only — it does not mention the API.
- **Still no machine-readable contract, confirmed the hard way.** `/openapi.json`, `/openapi.yaml`, `/swagger.json`, `/v1/openapi.json`, `/api-docs`, `/redoc` and `/graphql` all 404 on the only host that resolves; `api.`, `docs.` and `status.` subdomains do not resolve at all. `openapi/anyimagedetector-ai-image-detector-openapi.yml` is **transcribed by API Evangelist** from the provider's HTML reference and is stamped as such in its `x-provenance` block — it is not a provider-published contract.
- **The documented endpoint is real and enforced.** An anonymous `POST /v1/image/detect` returned `401 {"error":"unauthorized","message":"Missing API key"}` — matching the published error envelope exactly.
- **Every `/.well-known/` path 404s**, including both agent-card locations. No `WellKnown`, `SecurityTxt` or `AgentCard` pointer was wired, because the provider serves none of those documents.
- **No SDKs, no CLI, no GitHub org.** Registry sweeps across npm, PyPI, RubyGems, crates.io, NuGet, Maven Central, pkg.go.dev and Packagist found no first-party package; `api.github.com/orgs/anyimagedetector` 404s.
- **The two gaps that matter most for API consumers:** there is **no idempotency key** on a billable POST (a retry after a timeout may be charged twice), and there are **no `RateLimit-*` headers** — only `Retry-After` on a 429 — so a client cannot see remaining budget before it hits the 1 req/sec ceiling.
- **A note on posture.** `robots.txt` disallows ClaudeBot, GPTBot, Google-Extended, CCBot, Bytespider, Amazonbot, Applebot-Extended and meta-externalagent, and sets Cloudflare Content Signals to `ai-train=no, use=reference` — while the product itself is sold as a machine surface for AI-related screening.
